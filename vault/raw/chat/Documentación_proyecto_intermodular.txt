Abstract


En el siguiente documento se describe nuestra propuesta para proyecto intermodular. Se explican sus funciones y detallan sus características técnicas, así como su público objetivo. El proyecto consta de un panel de macros físico controlado por un ESP32 y una aplicación de escritorio en Java que permite configurar todas sus funciones de forma intuitiva.




1. Introducción


Nuestro proyecto consiste en un panel de teclas diseñado (figura 1) para ofrecer una experiencia práctica, sencilla y totalmente adaptable. Cada tecla puede ejecutar una o varias acciones al ser pulsada, lo que permite automatizar tareas o combinaciones que normalmente requerirían más tiempo. También hemos programado una aplicación de escritorio para poder reconfigurar las teclas y potenciómetros.


Además, el usuario tiene la posibilidad de personalizar por completo las funciones asignadas a cada botón, ajustándose a sus necesidades y forma de trabajar. De esta manera, el dispositivo no solo mejora la comodidad y la eficiencia, sino que también se adapta a distintos usos, ya sea en entornos de trabajo, ocio o creación de contenido.


El sistema se comunica de dos formas: mediante USB para la configuración desde la aplicación de escritorio y mediante Bluetooth para la ejecución de las macros como si de un teclado físico se tratara.




2. Presentación general del producto


2.1 Usos y aplicaciones


El panel está pensado para ser una herramienta multifuncional, capaz de integrarse en distintos tipos de trabajo. En el ámbito de la programación, puede emplearse para compilar y ejecutar código, abrir un entorno de desarrollo, ejecutar comandos en la terminal o insertar fragmentos de código que se utilicen con frecuencia. Estas funciones permiten ahorrar tiempo y mantener un flujo de trabajo más ordenado.


Para los creadores de contenido y streamers, el panel puede configurarse para controlar plataformas como OBS o Streamlabs, facilitando el cambio de escenas, el control del audio o la activación de efectos durante una transmisión en vivo. Esto reduce la necesidad de usar el teclado o el ratón constantemente, brindando una experiencia de transmisión más fluida.


En el campo del diseño gráfico y la edición multimedia, el dispositivo permite asignar combinaciones de teclas o herramientas en programas como Photoshop, Illustrator o Blender. De esta manera, el usuario puede realizar acciones repetitivas —como cambiar de herramienta, aplicar filtros o guardar archivos— con un solo toque.


Incluso en un entorno cotidiano, el panel puede servir para automatizar acciones simples, como abrir programas, iniciar una reunión en línea o controlar dispositivos inteligentes. Su flexibilidad lo convierte en una herramienta útil para cualquier persona que desee mejorar su productividad frente al ordenador.


2.2 Público objetivo


El panel está dirigido principalmente a programadores y desarrolladores de software, quienes se benefician directamente de la automatización de comandos y atajos. No obstante, su diseño adaptable y su facilidad de configuración lo hacen atractivo para otros perfiles, como streamers, diseñadores, músicos digitales y usuarios que buscan optimizar su tiempo frente al ordenador.


Su carácter abierto y programable permite personalizarlo para diferentes usos, lo que amplía considerablemente su público potencial. Todo esto a través de nuestra propia aplicación, la cual facilita la modificación de su comportamiento de una manera ágil, simple e intuitiva.


3. Descripción técnica del hardware


3.1 Características del producto


El panel de macros con ESP32 (figura 2) se caracteriza por su versatilidad y adaptabilidad. Gracias a su conexión USB, puede alimentarse directamente desde el computador y recibir comandos de configuración, evitando el uso de fuentes externas. Además, el ESP32 incorpora conectividad Bluetooth BLE (Bluetooth Low Energy), lo que permite que el ordenador lo reconozca como un teclado HID inalámbrico para ejecutar las macros sin necesidad de cables.


La carcasa y el soporte (figuras 3 y 4) son fabricados mediante impresión 3D, lo que permite personalizar completamente el diseño y optimizar el espacio interno para los componentes electrónicos.


Las teclas del panel son totalmente programables y personalizables, ya que se pueden cambiar los switches mecánicos para una mayor personalización táctil y de respuesta.


El dispositivo es compatible con los principales sistemas operativos (Windows, macOS y Linux) y puede configurarse mediante nuestra aplicación de escritorio, la cual cuenta con una interfaz de usuario y herramientas de configuración de macros, perfiles y funciones de potenciómetros.

3.3 Diseño de la carcasa


La carcasa se diseñó para alojar de forma ordenada todos los componentes del Stream Deck, dejando accesibles botones, potenciómetros y pantalla en la parte superior y lateral.
  
 Prototipo de diseño de la carcasa
  

Diseño final 


Se buscó un formato compacto, funcional y modular, dividido en dos piezas: una base principal y una tapa frontal. Esto permite que se pueda reutilizar la base y solo cambiar el panel central al añadir más switches, potenciómetros u otros componentes en futuras revisiones.


La base de carga incluye un compartimento para el receptor Qi, permitiendo cargar el dispositivo simplemente colocándolo sobre una base de carga inalámbrica.

3.5 Errores y soluciones durante el desarrollo


Envío de componentes:


No se tuvo en cuenta que algunos componentes, como la batería, no podían enviarse a Mallorca, lo que retrasó parte del montaje.
Solución: Se compraron en tienda física baterías de vapeador con características equivalentes a las necesarias para el proyecto.


Peso de la estructura:


Al estar la base impresa en 3D y usar componentes muy ligeros, el conjunto tenía poco peso y resultaba inestable.
Solución: Se diseñaron dos compartimentos para introducir pesos de pesca de 200 g y se rellenaron con arcilla, formando bloques sólidos que aumentan la estabilidad de la base.


Errores de impresión 3D:


Aparecieron errores por medidas incorrectas de algunos componentes, mala distribución interna y paredes excesivamente gruesas, lo que obligó a descartar varias piezas impresas.
Solución: Se revisaron las medidas, se ajustó el diseño de la carcasa y se reimprimieron las piezas con las dimensiones corregidas.


4. Guía de usuario
4.1 Primeros pasos


Conexión del dispositivo:


1. Conecta el Teclado de Macros al ordenador mediante el cable USB.


2. Abre la aplicación de escritorio "AplicacionTeclado".


3. La aplicación detectará automáticamente el dispositivo y mostrará en consola: [SERIAL] Conectado a COMX.


Emparejamiento Bluetooth:


Nota: La conexión Bluetooth es necesaria para que las macros se ejecuten como pulsaciones de teclado reales en el ordenador.


1. En la pantalla OLED del dispositivo aparecerá "BLE Listo - Emparejar PC".


2. En tu ordenador, ve a Configuración → Bluetooth y dispositivos → Agregar dispositivo.


3. Selecciona "Teclado Macros" de la lista de dispositivos disponibles.


4. Cuando la conexión se establezca, la pantalla OLED mostrará "BLE Conectado" y el indicador BLE:OK.
4.2 Configuración de teclas


Seleccionar una tecla:
1. En la aplicación, haz clic en la pestaña "Teclas" del panel lateral izquierdo.


2. Verás 6 botones numerados (Botón 1 a Botón 6). Haz clic en aquel que quieras configurar.


3. El botón seleccionado se resaltará en verde.


Asignar una acción:


En el panel derecho aparecerán las opciones de configuración, donde podrás elegir entre dos modos mediante un selector deslizante:


- Modo APP: Permite asignar atajos de teclado o aplicaciones predefinidas. Opciones disponibles: Chrome, Ctrl+C, Ctrl+V, Spotify, Calculadora. Al seleccionar una opción, se asigna automáticamente a la tecla.


- Modo URL: Permite asignar direcciones web personalizadas. Escribe la URL en el campo de texto (ej: https://github.com). Pulsa "Agregar URL" para añadirla a la lista. Selecciona la URL de la lista desplegable.


Enviar la configuración:
1. Pulsa el botón verde "Enviar al dispositivo".
2. El botón mostrará "✓ ¡Enviado!" como confirmación durante 1,5 segundos.
3. La configuración queda guardada en el perfil actual.


Usar la tecla:
- Pulsa físicamente la tecla configurada en el panel.
- La macro se ejecutará inmediatamente en el ordenador a través de Bluetooth.


4.3 Configuración de potenciómetros


Seleccionar un potenciómetro:


1. En la parte superior del panel de configuración, haz clic en uno de los dos círculos.
2. El círculo seleccionado se resaltará en verde.


Asignar una función:


En el panel derecho aparecerán las opciones disponibles:
- Volumen: Controla el volumen del sistema operativo.
- Brillo de pantalla: Controla el brillo (efectivo solo en pantallas integradas de portátiles).


Enviar la configuración:


1. Selecciona la función deseada.
2. Pulsa el botón verde "Enviar al dispositivo".
3. La configuración se envía exclusivamente para el potenciómetro seleccionado.


Usar el potenciómetro:


- Gira físicamente el potenciómetro en el panel.
- El volumen o brillo del sistema cambiará en tiempo real.
- La pantalla OLED mostrará "Volumen" o "Brillo" con el mensaje "Cambiando...".


4.4 Gestión de perfiles


¿Qué es un perfil?
Un perfil almacena la configuración completa de las 6 teclas y 2 potenciómetros. Permite mantener múltiples configuraciones para distintos escenarios de uso (trabajo, gaming, streaming, etc.). Los perfiles se guardan en el disco y persisten entre sesiones.


Crear un perfil nuevo:


1. Ve a la pestaña "Perfiles" del panel lateral izquierdo.
2. Haz clic en el botón "+".
3. Escribe un nombre para el nuevo perfil en el diálogo que aparece.
4. Pulsa Aceptar. El nuevo perfil se creará con las teclas vacías y los potenciómetros en sus funciones por defecto.


Cambiar entre perfiles:


1. Haz clic en el nombre del perfil que quieras usar.
2. La configuración se cargará automáticamente desde el disco.
3. Se enviará al dispositivo conectado.


Guardar cambios:


- Después de modificar teclas o potenciómetros, ve a la pestaña Perfiles.
- Pulsa el botón azul " Guardar perfil actual".
- El botón mostrará " ¡Perfil guardado!" como confirmación.
- Importante: La aplicación también guarda automáticamente al cerrarse y al cambiar de perfil.


Eliminar un perfil:


1. Selecciona el perfil que quieras eliminar.
2. Nota: No se puede eliminar el perfil "Default".
3. Pulsa el botón rojo "🗑️ Eliminar perfil".
4. Confirma la eliminación en el diálogo de advertencia.
5. Se cargará automáticamente otro perfil disponible.

5. Presentación general de la app


  

Diseño figma de la Interfaz 


Además del hardware, se ha desarrollado una aplicación de escritorio complementaria en Java, destinada a configurar y personalizar las funciones del panel, así como los potenciómetros integrados.


La aplicación sigue una arquitectura MVC (Modelo-Vista-Controlador) y utiliza el tema oscuro FlatLaf para una apariencia moderna. Se comunica con el ESP32 mediante puerto serie USB (usando la librería jSerialComm) para enviar la configuración de macros y recibir confirmaciones.


El usuario tiene la posibilidad de definir completamente el comportamiento de cada botón, crear y gestionar perfiles de configuración, y adaptar el dispositivo a su entorno y estilo de trabajo.


De esta manera, el panel no solo mejora la comodidad y eficiencia del usuario, sino que también se adapta a distintos contextos de uso: desde entornos de trabajo técnico o creativo hasta aplicaciones de ocio o productividad personal.


5.1 Funcionalidad


La aplicación de escritorio permite configurar las diferentes opciones que ofrece el teclado de macros. La interfaz contiene dos secciones principales de configuración: teclas y potenciómetros. Cada una con su propio panel de opciones y botón de envío al dispositivo.


El teclado macros cuenta con una aplicación de escritorio preparada para configurar las diferentes opciones que puede llegar a ofrecer. Dicha aplicación consiste en una interfaz que contiene opciones de configuración de teclas. 


  

Paneles de configuración


Cada tecla se configura individualmente. Podremos dotar a la tecla de diferentes funciones, de tal modo que al ser presionada, actuará según la opción programada en la aplicación.


Las teclas disponen de dos tipos principales de acción: ejecutar aplicación y abrir URL.


El modo de ejecución de aplicación consiste en iniciar la aplicación que se especifique ya sea un programa de escritorio o una función del sistema operativo. 


El modo de enlaces URL permite guardar direcciones y asignarlas al botón para que este las abra en navegador directamente con un solo movimiento.


Además de las teclas también contamos con los potenciómetros, los cuales se enfocan en ciertas funciones más específicas como control de volumen de sonido o iluminación de pantalla. Estos también son modificables en la aplicación.




  

Interfaz de la aplicación


Configuración de teclas:


Cada tecla se configura individualmente. Se le pueden asignar diferentes funciones, de tal modo que al ser presionada, actuará según la opción programada en la aplicación. Las teclas disponen de dos tipos principales de acción:


- Ejecutar aplicación: Inicia una aplicación del sistema o una combinación de teclas (atajos como Ctrl+C, Ctrl+V). Las aplicaciones predefinidas incluyen Chrome, Spotify y Calculadora.
- Abrir URL: Guarda direcciones web y las asigna al botón para que este las abra en el navegador directamente con un solo movimiento.


Configuración de potenciómetros:
Los potenciómetros se enfocan en funciones de control del sistema: volumen de sonido (subir/bajar) y brillo de pantalla (subir/bajar). Estas funciones también son modificables desde la aplicación y se envían al dispositivo mediante el botón "Enviar al dispositivo".


Gestión de perfiles:
La aplicación permite crear, cargar, guardar y eliminar perfiles de configuración. Cada perfil almacena la configuración completa de las 6 teclas y 2 potenciómetros, permitiendo al usuario cambiar rápidamente entre configuraciones para distintos escenarios (trabajo, gaming, streaming, etc.). Los perfiles se guardan en disco y persisten entre sesiones.

6. Descripción técnica de la app


La aplicación ha sido desarrollada en Java 17 y sigue una arquitectura MVC (Modelo-Vista-Controlador) con una capa adicional de servicios para la comunicación con el hardware. El proyecto se construye con Maven y utiliza las siguientes dependencias: FlatLaf 3.7 (tema oscuro moderno para la interfaz Swing) y jSerialComm 2.11.0 (comunicación serie USB con el ESP32).


La arquitectura se organiza en los siguientes paquetes:




Paquete
	Función
	model
	Clases de datos (Key, Knob, Macro, Profile) y servicios (DeviceService, ProfileRepository)
	controller
	Controladores que coordinan vista y modelo (DeviceController, KeyConfigController, ProfileController, NavigationController)
	view
	Interfaz gráfica con Swing (MainView, KeyConfigPanel, ProfileManagerView, botones personalizados)
	main
	Clase principal AplicacionTeclado que orquesta la inicialización
	



La comunicación con el ESP32 se realiza mediante comandos de texto por puerto serie USB (115200 baudios):




Comando
	Formato
	Función
	SET_KEY
	SET_KEY:<1-6>:<macro>
	Asigna una macro a una tecla
	SET_POT
	SET_POT:<1-2>:<funcion>
	Asigna una función a un potenciómetro
	



La aplicación implementa un sistema de perfiles que permite persistir configuraciones en disco, así como guardado automático al cerrar la aplicación y al cambiar de perfil.

	11. Documentación de la App
11.1 Propósito


La aplicación de escritorio complementaria al Teclado de Macros es una herramienta gráfica desarrollada en Java que permite al usuario configurar, gestionar y enviar al hardware todas las funciones del dispositivo sin necesidad de conocimientos técnicos. Sus propósitos fundamentales son:


Configuración visual de macros: Ofrecer una interfaz gráfica intuitiva para asignar combinaciones de teclas, aplicaciones o URLs a cada una de las 6 teclas físicas del panel.


Configuración de potenciómetros: Permitir asignar funciones de control del sistema (volumen, brillo) a los 2 potenciómetros del dispositivo.


Comunicación bidireccional con el ESP32: Establecer un canal de comunicación por puerto serie USB para enviar la configuración al microcontrolador y recibir confirmaciones y datos de estado en tiempo real.


Gestión de perfiles: Crear, cargar, guardar y eliminar perfiles de configuración que persisten en disco, permitiendo al usuario mantener múltiples configuraciones para distintos escenarios de uso (trabajo, gaming, streaming, etc.).


Retroalimentación visual: Mostrar en consola y en la interfaz gráfica el estado de la conexión con el dispositivo, el envío de datos y las acciones realizadas.
11.2 Explicación del código fuente


El proyecto sigue una arquitectura MVC (Modelo-Vista-Controlador) modificada con una capa adicional de servicios para la comunicación con el hardware. El código se organiza en los siguientes paquetes:


11.2.1 Paquete model — Capa de Lógica


Contiene las clases que representan el estado del sistema y la lógica de persistencia.


* model.hardware.Key


Representa una tecla física del panel. Contiene: id: Identificador numérico (0-5) de la tecla. macro: Objeto Macro asociado a la tecla (puede ser null si no está configurada). Implementa Serializable para permitir su persistencia en disco como parte de un perfil.


* model.hardware.Knob


Representa un potenciómetro del panel. Contiene: id: Identificador numérico (0-1) del potenciómetro. function: Enumeración Function que puede ser VOLUME, BRIGHTNESS, SCROLL o ZOOM. La enumeración interna Function define las funciones asignables a cada potenciómetro.


* model.macro.Macro


Representa una macro o acción asignada a una tecla. Contiene: name: Nombre descriptivo de la macro (ej: "Abrir Chrome"). actions: Lista de cadenas que describen las acciones a ejecutar. Cada acción sigue el formato OPEN_APP:nombre o OPEN_URL:url.


* model.macro.MacroFactory


Clase factoría que crea objetos Macro estandarizados. Métodos principales: createAppMacro(String appName): Crea una macro del tipo OPEN_APP:<nombre>. createUrlMacro(String url): Crea una macro del tipo OPEN_URL:<url>.


* model.profile.Profile


Representa un perfil completo de configuración. Contiene: name: Nombre del perfil (usado como nombre de archivo). keys: Lista de 6 objetos Key con sus macros asignadas. knobs: Lista de 2 objetos Knob con sus funciones asignadas.


* model.profile.ProfileRepository


Gestiona la persistencia de perfiles en el sistema de archivos. Métodos: save(Profile): Serializa y guarda un perfil en la carpeta profiles/ con extensión .dat. load(String name): Carga y deserializa un perfil desde disco. listAll(): Lista todos los perfiles disponibles. delete(String name): Elimina un perfil del disco.


* model.device.DeviceService (Interfaz)


Define el contrato para la comunicación con el hardware. Métodos: connect() / disconnect(): Gestionan la conexión. isConnected(): Verifica el estado de la conexión. sendProfile(Profile): Envía un perfil completo al ESP32. sendKnobConfig(int, String): Envía la configuración de un solo potenciómetro.


* model.device.SerialDeviceService


Implementación real de DeviceService usando la librería jSerialComm. Conexión: Escanea puertos COM disponibles, configura 115200 baudios, 8 bits de datos, 1 bit de parada, sin paridad. Envío de comandos: Construye comandos SET_KEY:<id>:<macro> y SET_POT:<id>:<función> a partir del modelo Java, traduciendo las funciones al formato esperado por el ESP32 (ej: VOLUME → VOLUMEN). Recepción de respuestas: Implementa un SerialPortDataListener que acumula datos en un StringBuilder y procesa línea a línea, mostrando las respuestas del ESP32 en consola. Método sendKnobConfig(): Envía un comando SET_POT individual sin necesidad de reenviar todo el perfil.


* model.device.MockDeviceService


Implementación simulada de DeviceService para desarrollo y pruebas sin hardware físico. Todos los métodos imprimen sus acciones en consola con el prefijo [SIM].


11.2.2 Paquete controller — Capa de Control


Contiene las clases que coordinan las interacciones entre la vista y el modelo.


* controller.DeviceController


Controlador para la comunicación con el dispositivo. Expone métodos connect(), sendProfile() e isConnected() que delegan directamente en el DeviceService inyectado.


* controller.KeyConfigController


Controlador principal para la configuración de teclas y potenciómetros. Implementa la interfaz KeyConfigListener: onAssignAppToKey(int, String): Asigna una macro de aplicación a una tecla usando MacroFactory. onAssignUrlToKey(int, String): Asigna una macro de URL a una tecla. onKnobFunctionChanged(int, Knob.Function): Actualiza la función de un potenciómetro en el modelo (sin enviar al ESP32 automáticamente). onSendToDevice(): Envía el perfil completo al ESP32 mediante DeviceService.sendProfile(). onSendKnobToDevice(int, Knob.Function): Envía solo la configuración de un potenciómetro específico mediante DeviceService.sendKnobConfig().


* controller.ProfileController


Controlador para la gestión de perfiles. Métodos: save(Profile): Guarda un perfil mediante el repositorio. load(String): Carga un perfil del disco. createNew(String): Crea un perfil nuevo con teclas vacías y knobs por defecto (VOLUMEN, BRILLO). listProfiles(): Lista los perfiles disponibles. delete(String): Elimina un perfil.


* controller.NavigationController


Gestiona la navegación entre paneles de la interfaz (Teclas, Perfiles) mediante listeners en los botones del ControlPanel.


11.2.3 Paquete view — Capa de Vista


Contiene las clases que construyen la interfaz gráfica con Swing.


* view.MainView


Ventana principal de la aplicación (hereda de JFrame). Tamaño: 1000×700 píxeles, no redimensionable. Layout: BorderLayout con ControlPanel al oeste y panel central con CardLayout para alternar entre vistas. IDs de paneles: KEY_CONFIG, PROFILE_MANAGER, DEVICE_STATUS.


* view.ControlPanel


Panel lateral de navegación con botones "Teclas" y "Perfiles". Usa ControlPanelButton (botones personalizados con efectos visuales de hover y glow). Mantiene el estado de selección único entre ambos botones.


* view.ProfileManagerView


Panel de gestión de perfiles. Muestra una cuadrícula de ProfileButtonView para cada perfil guardado. Botón "+" para crear nuevo perfil (abre diálogo JOptionPane para el nombre). Botón "Guardar perfil actual" (azul) para persistir los cambios. Botón " Eliminar perfil" (rojo) con confirmación de diálogo. Etiqueta informativa que muestra el perfil activo e instrucciones. Comunicación con el controlador mediante 4 callbacks: onProfileSelected, onProfileCreated, onSaveProfile, onDeleteProfile.


* view.panels.keyconfig.KeyConfigPanel


Panel principal de configuración de teclas y potenciómetros. Contiene KnobGridPanel (2 potenciómetros), KeyGridPanel (6 teclas) y OptionsPanel con CardLayout para alternar entre KeyOptionsPanel y KnobOptionsPanel. Gestiona la selección visual: al hacer clic en una tecla o potenciómetro, se resalta y se muestra su panel de opciones correspondiente.


* view.panels.keyconfig.KeyGridPanel


Cuadrícula de 6 botones MacroButtonView dispuestos en 2 columnas × 3 filas. Cada botón muestra "Botón X" y al hacer clic notifica al listener con su índice.


* view.panels.keyconfig.KnobGridPanel


Panel con 2 botones KnobButtonView (botones circulares con indicador visual). Dispuestos horizontalmente alineados con las columnas de las teclas.


* view.panels.keyconfig.KeyOptionsPanel


Panel de opciones para una tecla seleccionada. Selector deslizante ToggleAppUrlPanel para alternar entre App y URL. Lista desplegable de aplicaciones predefinidas: Chrome, Ctrl+C, Ctrl+V, Spotify, Calculadora. Campo de texto y botón para añadir URLs. Lista desplegable de URLs añadidas. Botón verde "Enviar al dispositivo" que llama a onSendToDevice().


* view.panels.keyconfig.KnobOptionsPanel


Panel de opciones para un potenciómetro seleccionado. Botones de radio: "Volumen" y "Brillo de pantalla". Botón verde "Enviar al dispositivo" que llama a onSendKnobToDevice().


* view.buttons


Contiene botones personalizados con efectos visuales: MacroButtonView: Botón rectangular con glow animado (azul en hover, verde al seleccionar). KnobButtonView: Botón circular con indicador de posición. ControlPanelButton: Botón de navegación con gradiente y glow. ProfileButtonView: Botón de perfil con tipo (PROFILE o ADD) y efectos de selección. SlideToggleBar: Control deslizante animado para alternar entre App/URL.


* view.panels.OptionsPanel


Contenedor con bordes redondeados y color de fondo semitransparente para los paneles de opciones.


11.2.4 Clase Principal


* main.AplicacionTeclado


Punto de entrada de la aplicación. Responsabilidades: Configurar el Look and Feel oscuro (FlatDarkLaf). Inicializar los servicios: SerialDeviceService y ProfileRepository. Crear los controladores: DeviceController, ProfileController, KeyConfigController. Cargar o crear el perfil inicial (si no hay perfiles, crea "Default"). Construir la vista principal y configurar los 4 callbacks de perfiles. Conectar con el ESP32 y enviar el perfil inicial. Configurar el guardado automático al cerrar la aplicación (WindowListener).


Los 4 callbacks de perfiles configurados son: Perfil seleccionado: Guarda el perfil actual, carga el seleccionado, actualiza el KeyConfigController con el nuevo perfil, refresca la UI y envía la nueva configuración al ESP32. Nuevo perfil creado: Guarda el perfil actual, crea uno nuevo, actualiza el controlador, refresca la lista de perfiles en la vista y envía el perfil vacío al ESP32. Guardar perfil: Persiste el perfil actual en disco mediante ProfileController.save(). Eliminar perfil: Elimina el perfil actual del disco (excepto "Default"), carga otro perfil disponible y lo envía al ESP32.

11.3.7 Consideraciones de Diseño


Bajo acoplamiento: La interfaz DeviceService permite cambiar entre implementación real (SerialDeviceService) y simulada (MockDeviceService) sin modificar el resto del código.

Persistencia simple: Los perfiles se guardan como archivos .dat en la carpeta profiles/ usando serialización nativa de Java.


Internacionalización parcial: El SerialDeviceService traduce funciones al español (VOLUME → VOLUMEN) para coincidir con el firmware del ESP32.


Separación de responsabilidades: Cada controlador gestiona un aspecto específico (dispositivo, teclas/knobs, perfiles, navegación).


12. Documentación del código del ESP32


12.1 Propósito


El firmware cargado en el microcontrolador ESP32 constituye el núcleo del sistema de hardware del Teclado de Macros. Su propósito principal es triple:


Actuar como periférico HID (Human Interface Device) mediante Bluetooth Low Energy (BLE), permitiendo que el ordenador lo reconozca como un teclado inalámbrico estándar.


Leer el estado físico de los 6 switches mecánicos y 2 potenciómetros, ejecutando las macros o funciones asignadas a cada uno.


Comunicarse con la aplicación de escritorio a través del puerto serie USB (COM), recibiendo comandos de configuración en tiempo real y respondiendo con confirmaciones o datos de estado.


El firmware implementa un protocolo de comunicación serie basado en texto que permite a la aplicación Java reconfigurar dinámicamente el comportamiento de cada tecla y potenciómetro sin necesidad de reprogramar el microcontrolador.

12.2.2 Report Descriptor HID


El reportDescriptor[] es una estructura binaria que define cómo el ordenador debe interpretar los datos enviados por el ESP32. Contiene dos secciones diferenciadas por su Report ID:


Report ID 1 — Teclado estándar: Define un teclado compatible con el estándar HID Keyboard Boot Protocol. Permite enviar 8 bytes donde el primer byte contiene los modificadores (Ctrl, Alt, Shift, GUI) y los bytes restantes contienen los códigos de las teclas pulsadas. Es compatible con todos los sistemas operativos.


Report ID 2 — Consumer Page (Multimedia): Implementa la página de consumo HID (Usage Page 0x0C), que permite enviar comandos multimedia como subir/bajar volumen, control de reproducción y ajuste de brillo. Utiliza valores de 16 bits para los códigos de consumidor, permitiendo una amplia gama de controles.


12.2.3 Sistema de lectura de teclas


Las 6 teclas mecánicas se leen mediante los pines GPIO 4, 5, 12, 13, 14 y 15 configurados como INPUT_PULLUP. Esto significa que en reposo, el pin lee HIGH (3.3V) gracias a la resistencia interna de pull-up. Al pulsar la tecla, el pin se conecta a GND y lee LOW. Se implementa un sistema de anti-rebote (debounce) con un retardo de 50 ms para evitar múltiples lecturas de una misma pulsación. Cuando se detecta una pulsación válida, se ejecuta la macro asociada mediante la función executeMacro().


12.2.4 Sistema de lectura de potenciómetros


Los 2 potenciómetros se leen a través de los pines GPIO 32 y 33 (ADC1). El ESP32 tiene un ADC de 12 bits (0-4095). El código lee el valor analógico actual, calcula la diferencia con el valor anterior y si la diferencia supera el umbral (potThreshold = 300) y ha pasado el tiempo de cooldown (200 ms), ejecuta la acción correspondiente. La dirección del giro (diff > 0 o diff < 0) determina si se sube o baja el volumen/brillo.

12.2.7 Pantalla OLED


La función updateDisplay() muestra en la pantalla OLED de 128×32 píxeles: Línea 1: Estado de la conexión BLE o nombre de la macro ejecutada. 12.2.8 Callbacks BLE


La clase MyServerCallbacks hereda de BLEServerCallbacks y gestiona dos eventos: onConnect: Se activa cuando un dispositivo (el PC) se conecta. Establece bleConnected = true y actualiza la pantalla. onDisconnect: Se activa cuando el dispositivo se desconecta. Establece bleConnected = false, actualiza la pantalla y reinicia la publicidad BLE para permitir una nueva conexión.

12.3.5 Gestión de estados


El sistema mantiene dos estados principales que determinan su comportamiento:


Estado de conexión BLE (bleConnected): true: Las teclas y potenciómetros ejecutan acciones reales. false: Solo se procesan comandos serie, las teclas y potenciómetros se ignoran. La pantalla muestra BLE:--.


Configuración de macros (keyMacros[] y potFunctions[]): Se modifican mediante comandos serie desde la App Java. Se mantienen en memoria RAM volátil durante la ejecución. Se pierden al reiniciar el ESP32 (la App los reenvía al conectar).


12.3.6 Consideraciones técnicas


Anti-rebote: Implementado mediante comparación temporal (50 ms) para evitar falsas pulsaciones.


Cooldown de potenciómetros: 200 ms entre acciones para evitar saturación de comandos BLE.


Umbral de potenciómetros: 300 unidades ADC (de 4095) para ignorar pequeñas fluctuaciones.


Reportes HID: Se envían reportes de 8 bytes para teclado y 2 bytes para multimedia, seguidos inmediatamente de un reporte vacío para simular la liberación de teclas.


Reconexión automática: Al desconectarse el BLE, el servidor reinicia automáticamente la publicidad.

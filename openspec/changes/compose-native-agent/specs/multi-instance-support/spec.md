## ADDED Requirements

### Requirement: Compose project name from .env
The system SHALL read `COMPOSE_PROJECT_NAME` from `.env` to set the compose project name. Each cerebro instance MUST have a unique project name to avoid container name collisions on the same host.

#### Scenario: First installation
- GIVEN a fresh clone of the cerebro virtual repository
- WHEN the user runs `start.bat` for the first time
- THEN `start.bat` checks if `.env` contains `COMPOSE_PROJECT_NAME`
- AND if missing, prompts the user for a project name or defaults to `cerebrovirtual`
- AND `docker compose -p <project_name> up -d --build` is executed

#### Scenario: Second instance on same host
- GIVEN an existing cerebro instance running as project `cerebro-app1`
- WHEN the user clones the repo to a new directory and sets `COMPOSE_PROJECT_NAME=cerebro-app2` in `.env`
- AND runs `start.bat`
- THEN all containers are created under project `cerebro-app2`
- AND no container name collisions occur with `cerebro-app1`

### Requirement: Parametrized ports per instance
The system SHALL read port assignments from `.env` for all exposed services. Each service port MUST be configurable to allow multiple instances on the same host.

#### Scenario: Default ports
- GIVEN a `.env` without custom port values
- WHEN the system starts
- THEN backend uses port 8000, frontend 5173, agent 8080, searxng 8888
- AND the docker-compose.yml uses `${BACKEND_PORT:-8000}` syntax

#### Scenario: Custom ports for second instance
- GIVEN a `.env` with `BACKEND_PORT=8001`, `FRONTEND_PORT=5174`, `AGENT_PORT=8081`, `SEARXNG_PORT=8889`
- WHEN the system starts
- THEN all services bind to the custom ports
- AND the frontend proxies API requests to the correct backend port

### Requirement: No inter-instance communication
Each cerebro instance MUST be isolated. Instances SHALL NOT share networks, volumes, or configuration. No instance SHALL be able to discover or communicate with another instance on the same host.

#### Scenario: Two instances running simultaneously
- GIVEN two cerebro instances running as separate compose projects on the same host
- WHEN instance A's agent tries to reach instance B's backend
- THEN the connection fails (different Docker networks)
- AND no shared volumes exist between instances

### Requirement: Container naming follows compose convention
The system MUST NOT set `container_name` in docker-compose.yml. Container names SHALL be generated by Docker Compose as `<project>-<service>-1` (or `<project>-<service>-<replica>` for scaled services).

#### Scenario: Inspect containers by project
- GIVEN a running cerebro instance with project name `cerebro-app1`
- WHEN the user runs `docker compose -p cerebro-app1 ps`
- THEN all services are listed with names like `cerebro-app1-backend-1`, `cerebro-app1-sistema-agente-1`, etc.
- AND no `container_name` is set in the compose file
